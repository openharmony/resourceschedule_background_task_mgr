# 编码要求

> 文档版本：v1.0
> 更新时间：2026-08-19
> 本文档汇总后台任务管理组件的编码与文档规范。

## 错误处理

| 规范项 | 要求　　　　　　　　　　　　　　　　　　　　 |
| --------| ----------------------------------------------|
| 错误码 | 使用 `bgtaskmgr_inner_errors.h` 定义的错误码 |

## IPC 接口规范

新增IPC接口时使用IDL机制。IDL 接口文件 `interfaces/innerkits/IBackgroundTaskMgr.idl` 定义了全部 IPC 方法，由 IDL 工具自动生成 Proxy 与 Stub 代码。

## 编码规范

函数应该尽量简洁，函数函数不要超过50行，函数最大深度不要超过4。
对于类似逻辑的代码尽量复用逻辑，不要产生重复代码。当要产生重复代码时，必须进行针对性重构。

## 并发场景处理

实际处理逻辑在`handler_`中执行，保证无并发问题。

## 文档命名规范

知识库采用按文档类型组织的结构，文档按 `knowledge/`、`spec/`、`design/` 三类目录组织，目录结构参考`AGENTS.md`。

## 文档更新规范

新增或更新文档时遵循以下步骤：

1. **确定文档类型与目录**：根据内容性质选择 `knowledge/`、`spec/`、`design/` 对应目录，按上述命名规范确定文件名。
2. **保持三类分离**：基本概念归入 `knowledge/`（除重大概念变更，轻易不做修改），规则、约束、功能演进方式归入 `spec/`，数据模型、上下文与场景、知识关联、演进与版本、代码与符号（类/方法/变量/IDL + 类图）归入 `design/`。
3. **保留图表语法**：所有 PlantUML 图必须保留 `@startuml`/`@enduml` 原始语法，表格不得裁剪。
4. **语言规范**：所有文档用中文撰写，固定文件名、命令名（如 `hb build`）、代码标识符（如类名 `BgTransientTaskMgr`）保持英文。
5. **更新索引**：新增/删除文档后，同步更新 `AGENTS.md` 中的知识库索引表，确保文档路径与说明一致。
6. **文档更新场景**：更新代码规格或架构时需要同步修改`spec/`、`design/`下文档。文档更新时需要同步更新最新版本更新时间和版本号。
